# 🛡️ Руководство по безопасности и развертыванию в Production: RegAI

Настоящий документ описывает комплексную систему многоуровневой защиты (**Defense-in-Depth**), защитные механизмы от взломов и инструкцию по безопасному выводу системы в сеть.

## 🔒 2. Сводка защитных механизмов от атак

| Тип атаки / Угроза | Как защищен проект RegAI |
| :--- | :--- |
| **DDoS и флуд запросами** | В Nginx настроены зоны `limit_req_zone` (до 30 r/s). В FastAPI встроен sliding-window rate limiter на уровне IP. |
| **Подбор паролей (Brute-Force)** | Эндпоинты `/api/v1/auth/login` и `/login/json` ограничены 10 попытками в минуту на IP. Пароли хешируются `bcrypt`. |
| **SQL-инъекции (SQL Injection)** | Все запросы идут через SQLAlchemy 2.0 ORM с авто-экранированием и параметризацией. |
| **Межсайтовый скриптинг (XSS)** | React экранирует данные по умолчанию + в HTTP-заголовках включен `X-XSS-Protection: 1; mode=block`. |
| **Clickjacking** | Заголовок `X-Frame-Options: DENY` запрещает встраивание сайта во враждебные iframe. |
| **MIME-Sniffing** | Заголовок `X-Content-Type-Options: nosniff` запрещает браузеру исполнять файлы с неверным MIME-типом. |
| **Перехват трафика (Man-in-the-Middle)** | `Strict-Transport-Security` (HSTS) принуждает браузеры использовать только шифрованный HTTPS (TLS 1.2/1.3). |
| **DoS через гигантские файлы** | Ограничение `client_max_body_size 35M` в Nginx и проверка `content-length` в FastAPI (код 413). |
| **Кража учетных данных 1С** | Пароли и API-токены интеграции с 1С шифруются в базе данных алгоритмом **AES-256 / Fernet** (модуль `crypto.py`). В API пароли никогда не отдаются открытым текстом. |
| **Уязвимости контейнера (Privilege Escalation)**| Бэкенд в Docker работает под непривилегированным пользователем `appuser` (UID 1000), а не под `root`. |

## 🚀 3. Пошаговая инструкция по выводу на VPS (Production)

### Шаг 1: Аренда сервера
- Арендуйте VPS с **Ubuntu 22.04 / 24.04 LTS** (рекомендуется Timeweb Cloud, Selectel или Hetzner).
- Характеристики: 2–4 CPU, 4–8 GB RAM, 50 GB SSD.

### Шаг 2: Настройка системного файрвола (UFW)
Подключитесь к серверу по SSH и включите брандмауэр:
```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp    # SSH
sudo ufw allow 80/tcp    # HTTP
sudo ufw allow 443/tcp   # HTTPS
sudo ufw enable
```

### Шаг 3: Автоматический запуск RegAI в 1 команду
```bash
# Клонируем проект
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd regai

# Запускаем автоматический скрипт деплоя
./deploy.sh
```
Скрипт сам:
1. Проверит и установит Docker и Docker Compose.
2. Сгенерирует случайные 64-символьные ключи шифрования `SECRET_KEY` и надежные пароли к БД в `.env`.
3. Соберет и запустит production-контейнеры.
4. Проведет миграции базы данных и создаст суперпользователя.

## 🌐 4. Подключение домена и бесплатного SSL-сертификата (HTTPS)

Чтобы проект открывался по красивому адресу (например, `https://demo.yourcompany.com`):

1. **В панели вашего регистратора доменов (Reg.ru, Beget, Cloudflare и др.):**
   - Добавьте **A-запись**: `demo.yourcompany.com` ➔ `IP_ВАШЕГО_СЕРВЕРА`.

2. **Установите Certbot для автоматического получения сертификата Let's Encrypt:**
   ```bash
   sudo apt update
   sudo apt install -y certbot
   
   # Получаем сертификат (укажите ваш домен и email)
   sudo certbot certonly --standalone -d demo.yourcompany.com --preferred-challenges http --agree-tos -m your-email@domain.com
   ```

3. Сертификаты автоматически будут обновляться каждые 90 дней через cron/systemd таймер `certbot renew`.

## 🔄 5. Обновление проекта (CI/CD / Manual Update)

Когда вы вносите новые изменения в код и хотите обновить сервер:
```bash
cd regai
git pull
docker compose up -d --build
```
Все пользовательские данные, база данных PostgreSQL и векторы ChromaDB сохраняются в постоянных томах (`volumes`) и не теряются при обновлениях.
